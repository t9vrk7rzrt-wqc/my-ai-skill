# DTC 建站 · 双端 UI 走查 → 飞书

**本 skill = 所有 DTC 建站的通用双端走查规范**（调用名：`UI走查-飞书` / `$ui-visual-audit-feishu`；团队同源：`ui-acceptance-assistant`）。  
**不是**某个品牌站、某一次 Home/PDP 的专用 skill。项目特例另放同目录专项文件或个人附录；**本对话/实战纠正过的通用规则只沉淀进本文件**。

提效助手，不替人拍板。证据门槛、最小单元拆解、高风险双证据；合并标注图、按容器量间距、视口敏感性、多语言去重、协作表保护。细节见 [reference.md](reference.md)，脚本见 `scripts/`。

## 0. 开工前（缺一项就先问）

- 线上 URL（各语言）、Figma file key + 各页 PC/移动 node-id（token 只在本机环境变量，**不回显、不写进文件**，结束提醒撤销）
- **范围：哪一页、哪一轮、哪一端/语言**；未点名禁止扩大
- 飞书：目标 Base/表 URL；先 `lark-cli auth status`，再读字段/视图；**用户的表优先，不自创选项**
- 基准视口：**PC 1920、移动 390**（其它宽度只判断是否宽度相关，不拿来逐像素比）
- 流程：先核表里旧问题是否已解决 → 再查新问题；**禁止抽查跳着看**，约定范围内模块/语言/双端逐项细查

## 1. 取证（每个模块两份证据）

1. **Figma**：`scripts/figma_boxes.py` → 文字参数、容器框；检查祖先链 `visible`
2. **线上**：`scripts/capture_live.js` → DOM + 计算样式 + 整页截图（懒加载、等字体）
3. **同尺度对齐**：`scripts/annotate.py`
4. 像素差分只辅助，必须映射回具体元素

### 截图硬规则
- 配图加载完成再截；大图 `complete && naturalWidth>40`；白底未出图禁止上传
- 抓图默认 `device_scale_factor≥2`；糊图不准当证据、不准据此判通过
- 图标对比要放大到能看清线形粗细

### 量法
- **间距量容器边到边**，不量内容（Logo/图标间距会骗人）
- 颜色同时报节点色值与渲染观感
- 无来源数值不硬写精确 px；可写偏大/偏小并勾需人工复核

**最小单元**：容器、边框、圆角、底色、阴影、图标、文字、间距、位置。  
**高风险双证据**：背景色、图标、文字样式、hover。

易漏七类（每模块、每端、每语言扫）：选中态、双层描边、双语文案、小图标粗细、圆角、间距（容器）、字号/字重/颜色。

## 2. 哪些写、哪些不写

- 只写差异；指明元素、现状、设计期望；用户口吻一句话
- 删掉肉眼无感的极小偏差
- 仅因设备切换导致的重排不记；基准视口下可见的要记
- 多语言去重：英德同问题只记英文；德语只记德语特有
- CMS/动态内容默认不算 UI 问题
- 用户已删的不重复加；设计稿自身问题单独提示
- **规范查出有问题的必须写入**；漏记大问题（如轮播未撑满）= 走查失败；禁止捡芝麻丢西瓜
- **约95%可放过接近项**；**95% 不覆盖用户已圈定/手补/点名问题**——必须继续不通过直到修好
- **禁止错模块对比、禁止胡编**；看不懂/对不齐就不写；用户肉眼觉得没问题优先信用户

---

## 3. 标注图（一二三四轮要求相同）

- 同模块同端合并一张：上设计稿 / 下线上
- **左上角写「设计稿」「线上」**；禁止多余符号/装饰
- **红框必须框在问题上**（图标框图标本体）；设计稿与线上对准同一元素；对不准整张重做
- 间距框空隙；同类多卡写「几张同样」
- 上传前读图验收：框位、清晰度、角标、无多余符号
- 用户手补行：优先用用户原标注图（可加角标整理，不换错模块）
- 图上中文禁止方框乱码（Arial Unicode / 冬青黑等）；失败中止，禁止 `load_default`

---

## 4. 问题描述与合并

短、直接：`【模块】元素 + 现状 → 设计稿` 或 `标注1…；标注2…；标注3…。需还原设计稿。`
- 用户已手改描述不覆盖
- **用户已补充过的问题禁止再补一遍**：同模块同现象不重开行、不重复贴同义说明；只核是否仍不通过，缺图才补图
- 文案类只写「文案和设计稿不一致」，不抄原文
- 各轮说明不写 px / 字号数字 / rgba / 宽高对比数字；禁止「原问题仍在」空话
- 配图清晰度统一写法：`线上配图和设计稿相比同位置过于模糊，需替换高清图`
- **同一模块最多 3 个标注一条**；写不下拆行（可 1～2 个）；配图详细、红框对准每个保留点
- 手补可合并进同模块行，**问题必须留下**，禁止误删、禁止再新建同现象

## 5. 写入飞书

结构以用户表为准：`页面` → `尺寸` → 模块顺序；语言、所属模块等照现有选项。  
默认：`前端是否完成优化` 不勾；`UI验收是否通过` 留空（复验后才填）。关键字段全空的空白行**直接删除**。

### 轮次门槛（禁止再犯）
- **前端未勾「是否完成优化」→ 禁止做二轮/三轮/四轮验收**
- 未勾优化：不写本轮说明、不贴本轮图
- 只有勾了优化，才开始对应轮次走查

### 页面范围（禁止再犯）
- **用户点名哪一页、哪一轮，只动那一页那一轮**；禁止猜、禁止全表、禁止改其它页
- 不确定先问

### 清误写二轮
- 只清本页：二轮说明 + 二轮图
- **≠ 删问题行**：问题描述、问题截图一律保留
- 若视图筛「待验收/不通过」：清完把未优化行改回 **待验收**，禁止留空导致分组消失

### 判定与复现
- 通过就是通过，不通过就是不通过；禁止用「约95%」把未修项改通过
- 曾通过又复现：取消优化✅；问题写入**后一轮**字段 + 对准图
- PC / 移动严格分开：只写对应端、只配对应端图；禁止「PC/移动同」

### 手补归模块
- **每条先展示用户原截图，再问归哪块**；禁止只抛文字
- 一次只确认一道红框 / 一对模块

### 协作表保护
- 写前拉最新；只动自己的记录；不静默改他人内容
- 用户改过的字段以用户为准
- 组内顺序 = 创建顺序：按页面模块自上而下建行；同模块相邻；禁止一行混多模块；补记禁止甩表尾

写入：`scripts/feishu_write.py` dry-run → 批量建 → 传附件 → 回读校验。

## 6. DTC 双端必核清单（首页/营销页与同类落地页）

> 以下从实战纠正沉淀为 **所有 DTC 建站** 通用必核项。模块名按当前站点实际命名对齐，不绑定某个品牌站。

每个出现的模块、每个端、每种语言都要主动核；**大问题优先于细项**。

| 模块类型（常见） | 必核 |
|---|---|
| Banner / 首屏 | 主标题折行/位置/文案/字号；按钮圆角与高度；配图清晰度 |
| Trust / 说明条 | 字号字重；竖条/分割线有无与样式；与下一模块间距 |
| 分类/入口卡 | 圆角；版心；标题/说明/链接字号与文案；**状态标签**样式与透明度；主图清晰度；与上下模块间距 |
| 奖项/背书卡 | 圆角；边框颜色；图文间分割线；字号字重；图标清晰度；模块间距 |
| 商品/内容轮播 | **是否撑满/两侧裁切**；卡片圆角；按钮圆角高度；字号文案；产品图清晰度；hover（如放大）是否实现；边框/分割线颜色；模块间距 |
| 视频 | 左右边距；封面圆角；播放图标大小/样式；封面清晰度 |
| 客户评价 | PC：轮播撑满/裁切、卡片样式、星星大小颜色、底部圆点、字号、与下模块间距；**移动：只对照移动稿实事求是，不强制套 PC「撑满」** |
| FAQ / 双栏问答 | 分隔横线；左右栏比例；左栏样式与内容完整性；字号；配图清晰度 |
| 模块↔模块间距 | 量容器边到边；每一对相邻模块是独立问题，不能互相顶替 |
| 状态标签（如 Coming Soon） | 样式、透明度、字号字重；同类多张写「几张同样」 |
| 边框 / 分割线 | 颜色与设计稿一致；缺失要记 |
| 配图清晰度 | PC+移动逐张；不够清晰统一记「需替换高清图」 |

口径：
- 对照**该端**设计稿；差距大才记
- 用户已圈的通栏/撑满/间距/标签优先于细项
- 不同模块的「未撑满」是两条，不能顶替
- 设计稿气泡里的交互（如 hover）按用户要求验收

## 决策树

```
开工前 → 确认：哪一页 + 哪一轮？未点名不动
前端未勾优化？ → 是 → 只整理一轮问题，禁止写二轮验收
发现差异 → 对照该端设计稿，差距大？ → 否 → 可不记（用户圈定除外）
         → 是 → 用户口吻写入（同模块可合并≤3）
写表前 → 用户是否已有同现象？ → 合并保留，勿重复、勿误删
      → 附图：设计稿+线上角标、红框在问题上、清晰
清误写二轮 → 只清本页二轮字段；状态改回待验收；不动问题描述/截图
曾通过又不行 → 取消优化✅ → 写入后一轮字段+图
空白全空 → 删除
```

## 经验纠错（本对话沉淀，禁止再犯）

1. 漏记轮播撑满/通栏等大问题 → 必须主动核、主动记  
2. 说明空话 + 错模块图 → 重写说明、换对准图  
3. 用户已补又重复补 → 禁止；可合并但勿删问题  
4. 用错模块图顶全表 / 换掉手补原图 → 禁止  
5. 「约95%」改通过未修项 / 用户圈定项 → 禁止  
6. 前端未勾优化就写二轮 → 禁止  
7. 清字段/走查扩大到未点名页 → 禁止；只动点名页那一轮  
8. 清二轮时把验收状态留空导致视图分组消失 → 清完改回「待验收」，不是删行  
9. 问手补归模块只发文字不附图 → 禁止；先贴用户原截图  
10. 移动端硬套 PC「撑满」口径 → 禁止；对照移动稿实事求是  
11. 纠正必须写回**本通用 skill**；禁止写成某品牌站专用 skill 标题
