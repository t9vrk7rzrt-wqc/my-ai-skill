# DTC 建站 · 双端 UI 走查 → 飞书

**本 skill = 所有 DTC 建站的通用双端走查规范**（本仓库目录：`ui-visual-audit-feishu`；调用名 `UI走查-飞书` / `$ui-visual-audit-feishu`；团队同源 `ui-acceptance-assistant`）。  
**不是**某个品牌站、某一次 Home/PDP 的专用 skill。项目特例另建专册；**实战纠正过的通用规则只沉淀进本文件**。  
合并原则：与团队原有验收条款**相同的合并**，本对话新增的**补上**；冲突时以用户当场纠正 + 本文件「轮次/范围/标注/合并」硬规则为准。

提效助手，不替人拍板。细节与命令见 [reference.md](reference.md)，脚本见 `scripts/`。

## 0. 开工前（缺一项就先问）

- 线上 URL（各语言；生产/预发/本地均可）
- 设计源：优先 Figma file/node；无 Figma 才用导出图，并问清对应端与模块
- 交互源（若要验交互）：优先 Figma 变体/原型/标注；否则录屏或书面说明；无来源则只测明显态，标为实现观察而非稿还原
- **范围：哪一页、哪一轮、哪一端/语言**；未点名禁止扩大
- 飞书：目标 Base/表 URL；先 `lark-cli auth status`，再读字段/视图；**用户的表优先，不自创选项**
- 基准视口：**PC 1920、移动 390**（对话确认硬口径）。平板或其它宽度仅当用户要求；否则只用于判断「是否宽度相关」
- 验收模式：`static-only`（默认静态）/ `full`（含交互）/ `interaction-followup`（后补交互）
- 流程：先核表里旧问题是否已解决 → 再查新问题；**禁止抽查跳着看**，约定范围内模块/语言/双端逐项细查
- token 只在本机环境变量；**不回显、不写进文件**；结束提醒撤销

平台无关：浏览器/Figma/截图/飞书写入可替换；缺能力就降级（CSV/Markdown/JSON）并写明阻塞点。不依赖单一 IDE 私有路径。

### Figma 批量

1. 单链接：只验该 `node-id` 对应页  
2. 整文件：列顶层画板，按序映射线上 URL 与飞书模块，自动逐板验收；交互补充板当作该模块状态标准，不是可选备注

## 1. 取证（每个模块两份证据）

1. **Figma**：`scripts/figma_boxes.py` / MCP → 文字参数、容器框；检查祖先链 `visible`  
2. **线上**：`scripts/capture_live.js` → DOM + 计算样式 + 整页截图（懒加载、等字体）  
3. **同尺度对齐**：`scripts/annotate.py`  
4. 像素差分只辅助，必须映射回具体元素；动画/轮播/粘性导致无法对齐时注明，相关行可勾「需人工复核」

### 截图硬规则
- 配图加载完成再截；大图 `complete && naturalWidth>40`；白底未出图禁止上传
- 抓图默认 `device_scale_factor≥2`；糊图不准当证据、不准据此判通过
- 图标对比要放大到能看清线形粗细
- 问题截图必须是本模块；禁止错滚动位置/错模块图
- 一条问题一张对准图；多条无关问题不要共用一张杂框图

### 量法
- **间距量容器边到边**，不量内容
- 颜色：同时报节点色值与渲染观感；浏览器外围黑底/透明 ≠ 页面底色（用目标元素 computed `background-color` + 同区截图）
- 无来源数值不硬写精确 px；写偏大/偏小并勾需人工复核
- 文案从 DOM 读，不靠截图认字

**最小单元**：容器、边框/描边粗细、圆角、底色、阴影、图标、文字层、间距、位置、默认/hover 等态——不能只看父容器。  
**高风险双证据**（缺一不写）：背景色、图标、文字样式、hover/交互态。两源冲突先复核视口/选择器/状态。

易漏七类（每模块、每端、每语言扫）：选中态、双层描边、双语文案、小图标粗细、圆角、间距（容器）、字号/字重/颜色。

### 组件类型清单（有则逐项）
- 导航/页头、页签、按钮、输入/搜索/下拉、卡片、标签、排版块、图/Logo/视频、图标、分割线/装饰、下拉/弹层、表格/列表/分页、页脚、轮播（框/箭头/圆点/裁切）
- Logo/社媒图标逐个核图形本身；重复/占位素材查真实 URL
- 标题前装饰条、CTA/播放钮拆子元素核；手型光标画板 = hover 参考，默认+hover 都要核

## 2. 哪些写、哪些不写

- 只写差异；指明元素、现状、设计期望；用户口吻一句话
- 删掉肉眼无感的极小偏差；只错一个属性就只写那个
- 仅因设备切换导致的重排不记；基准视口下可见的要记（可备注「宽度相关」）
- 多语言去重：英德同问题只记英文；德语只记德语特有
- CMS/动态内容：默认只验样式结构，不因内容/顺序不同报 UI 问题（除非用户要求验内容）
- 用户已删的不重复加；设计稿自身问题单独提示
- **规范查出有问题的必须写入**；漏记大问题（轮播未撑满/通栏等）= 走查失败；禁止捡芝麻丢西瓜
- **约95%可放过接近项**；**95% 不覆盖用户已圈定/手补/点名问题**
- **禁止错模块对比、禁止胡编**；看不懂/对不齐就不写；用户肉眼觉得没问题优先信用户
- 无交互源时，不要把缺 hover 当稿还原缺陷（可标交互待补充）

## 3. 标注图（一二三四轮要求相同）

- 同模块同端合并一张：上设计稿 / 下线上（或左右并排）
- **左上角写「设计稿」「线上」**；禁止多余符号/装饰
- **红框必须框在问题上**（糊图就框产品图本体，图标就框图标本体；禁止飘到标题空白/相邻文字）；设计稿与线上对准**同一元素同一位置**；对不准整张重做，禁止凑合上传
- 间距框空隙；同类多卡写「几张同样」
- 上传前读图验收：框位、清晰度、角标、无多余符号
- 用户手补行：优先用用户原标注图（可加角标整理，不换错模块）
- 图上中文禁止方框乱码（Arial Unicode / 冬青黑等）；失败中止，禁止 `load_default`

### 错图对照（禁止再犯）
| 问题说的是 | 禁止贴 | 应贴 |
|---|---|---|
| Banner/首屏 | 评价/FAQ 等 | Banner 对比 |
| Trust/说明条 | Banner | Trust 对比 |
| 分类/奖项/商品轮播/视频/评价/FAQ | 任意顶栏或其他模块 | 对应模块 |
| PDP 页签/技术表/保修/下载 | gallery 糊图、无关 underline | 该区实拍对比 |
| 用户手补短描述 | AI 自选 Banner | 用户原图 |

## 4. 问题描述与合并

短、直接：`【模块】元素 + 现状 → 设计稿`  
或：`标注1…；标注2…；标注3…。需还原设计稿。`  
各轮说明：`{模块}：{元素}{现状}，需还原设计稿。`（或直接写问题，不硬套前缀）

- **禁止在问题描述/各轮说明里再写「PC端」「移动端」**：表里已有「尺寸」字段，端信息已在行内，写了属多此一举
- 用户已手改描述不覆盖；相关新发现另起一行靠近该模块
- **用户已补充过的问题禁止再补一遍**：同模块同现象不重开行、不重复贴同义说明；只核是否仍不通过，缺图才补图
- 文案类只写「文案和设计稿不一致」，不抄原文
- 各轮说明/问题描述不写 px / 字号数字 / rgba / 宽高对比数字；禁止「原问题仍在」空话
- 配图清晰度统一写法：`线上配图和设计稿相比同位置过于模糊，需替换高清图`
- **同一模块最多 3 个标注一条**；写不下拆行（可 1～2 个）；配图详细、红框对准每个保留点
- 手补可合并进同模块行，**问题必须留下**，禁止误删、禁止再新建同现象
- 有把握的成因可带一句（切图层错/缺蒙版/素材未换/未用高清图）

## 5. 写入飞书

**用户现有表结构优先**（字段名/选项/视图以实表为准）。常见字段含：问题描述、页面、尺寸、所属模块、语言、问题截图、优先级、问题类型、需人工复核、前端是否完成优化、UI验收是否通过、备注说明、提出时间等。

默认：`前端是否完成优化` 不勾；`UI验收是否通过` 留空（复验后才填）；`需人工复核` 默认不勾。关键字段全空的空白行**直接删除**。

新站一表：不同官网不要写进旧站表；新建表可复用字段模板，但 `所属模块`/页面选项按新站信息架构重建。

### 轮次门槛（禁止再犯）
- **前端未勾「是否完成优化」→ 禁止做二轮/三轮/四轮验收**
- 未勾优化：不写本轮说明、不贴本轮图
- 只有勾了优化，才开始对应轮次走查

### 页面范围（禁止再犯）
- **用户点名哪一页、哪一轮，只动那一页那一轮**；禁止猜、禁止全表、禁止改其它页
- 不确定先问

### 清误写二轮
- 只清本页：二轮说明 + 二轮图
- **≠ 删问题行**：问题描述、问题截图一律保留
- 若视图筛「待验收/不通过」：清完把未优化行改回 **待验收**，禁止留空导致分组消失

### 判定与复现
- 通过就是通过，不通过就是不通过；禁止用「约95%」把未修项改通过
- 仍不对：不通过；取消优化✅；写本轮说明+对准图
- 曾通过又复现：取消优化✅；问题写入**后一轮**字段（二轮→三轮→四轮）+ 对准图
- 证据不足：先重做证据；仍不确定勾需人工复核并问用户
- PC / 移动严格分开：只写对应端、只配对应端图；禁止「PC/移动同」

### 手补归模块
- **每条先展示用户原截图，再问归哪块**；禁止只抛文字
- 一次只确认一道红框 / 一对模块

### 协作表保护与顺序
- 写前拉最新；只动自己的记录；不静默改他人内容
- 用户改过的字段以用户为准；不恢复用户已删/已隐藏列
- 组内顺序 = 创建顺序：按页面模块自上而下建行；同模块相邻；禁止一行混多模块；补记禁止甩表尾
- 共享未修组件：不重复深挖建重复行，交付里引用已有记录
- 写入：`scripts/feishu_write.py` dry-run → 批量建（≤200/批）→ 传附件 → 回读（高风险/需人工复核必回读）

### 问题类型 / 优先级（表内有则选用）
- 类型按缺陷本身选：基础视觉还原、交互还原、动效/动画还原、适配兼容、切图模糊、内容更新、效果优化、二次优化、其余视觉还原、其他（少用）
- 一条含两类缺陷就拆开
- P0 阻塞 / P1 高 / P2 中 / P3 低（定义见 reference）

### 需人工复核
仅证据不足且复核后仍不确定时勾；不要用它掩盖偷懒。完全确认的不勾；不确定且用户未要求存疑项 → 宁可不写。

## 6. DTC 双端必核清单（首页/营销页与同类落地页）

> 实战纠正沉淀为 **所有 DTC 建站** 通用必核。模块名按当前站点实际命名对齐，不绑定品牌站。

每个出现的模块、每个端、每种语言都要主动核；**大问题优先于细项**。

| 模块类型（常见） | 必核 |
|---|---|
| Banner / 首屏 | 主标题折行/位置/文案/字号；按钮圆角与高度；配图清晰度 |
| Trust / 说明条 | 字号字重；竖条/分割线有无与样式；与下一模块间距 |
| 分类/入口卡 | 圆角；版心；标题/说明/链接字号与文案；**状态标签**样式与透明度；主图清晰度；模块间距 |
| 奖项/背书卡 | 圆角；边框颜色；图文间分割线；字号字重；图标清晰度；模块间距 |
| 商品/内容轮播 | **是否撑满/两侧裁切**；卡片圆角；按钮圆角高度；字号文案；产品图清晰度；hover（如放大）；边框/分割线颜色；模块间距 |
| 视频 | 左右边距；封面圆角；播放图标大小/样式；封面清晰度 |
| 客户评价 | PC：轮播撑满/裁切、卡片样式、星星大小颜色、底部圆点、字号、与下模块间距；**移动：只对照移动稿实事求是，不强制套 PC「撑满」** |
| FAQ / 双栏问答 | 分隔横线；左右栏比例；左栏样式与内容完整性；字号；配图清晰度 |
| 模块↔模块间距 | 量容器边到边；每一对相邻模块是独立问题，不能互相顶替 |
| 状态标签（如 Coming Soon） | 样式、透明度、字号字重；同类多张写「几张同样」 |
| 边框 / 分割线 | 颜色与设计稿一致；缺失要记 |
| 配图清晰度 | PC+移动逐张；不够清晰统一记「需替换高清图」 |
| 版心 / 指示点 / 圆角 | 首页营销页常漏，主动量主动记 |

口径：对照**该端**设计稿；差距大才记；用户已圈通栏/撑满/间距/标签优先；不同模块「未撑满」是两条。

响应式另核（在范围内时）：无横向溢出、导航适配、图视频裁切比例、文字可读不重叠、主 CTA 可用。

技术信号（平台暴露时）：控制台错误、失败请求、基础 SEO/无障碍/性能风险——按用户要求写入，不默认冲淡视觉主线。

## 7. 效率不降质

- 先锁范围再开工；不擅自扩页
- 够用证据即可；DOM/CSS 已证明可跳过差分；高风险仍双证据
- 按模块批量采集，大 JSON 落盘不贴聊天
- 同壳复用证据，只增量查内容区
- 重复同构组件：深挖首个，其余核等价；独特图形/手型 hover 组件必须全核
- 聊天只给结论+数量+限制；证据进飞书附件

不可为提速砍掉：最小单元、子图标文字层、双态、证据门、协作表保护、轮次门槛、页面范围。

## 决策树

```
开工前 → 确认：哪一页 + 哪一轮？未点名不动
前端未勾优化？ → 是 → 只整理一轮问题，禁止写二轮验收
发现差异 → 对照该端设计稿，差距大？ → 否 → 可不记（用户圈定除外）
         → 是 → 用户口吻写入（同模块可合并≤3）
写表前 → 用户是否已有同现象？ → 合并保留，勿重复、勿误删
      → 附图：设计稿+线上角标、红框在问题上、清晰
清误写二轮 → 只清本页二轮字段；状态改回待验收；不动问题描述/截图
曾通过又不行 → 取消优化✅ → 写入后一轮字段+图
空白全空 → 删除
```
