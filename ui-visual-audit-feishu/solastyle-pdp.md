# SolaStyle 商品详情页（PDP）逐套走查专项

适用：SolaStyle（德国光伏电商）商品详情页按“第 N 套产品详情页”走查，设计稿对线上，问题写入飞书走查表。
通用取证、标注图、协作表保护、写入与回读流程见 [SKILL.md](SKILL.md) 与 [reference.md](reference.md)；**本文件只补该项目的专项规则，冲突时以本文件为准**。证据（截图、整页图、表格行）留在授权项目目录，不放进仓库。

## 1. 表与口径

- 字段沿用用户表：`页面`（如“第二套产品详情页”）、`尺寸`（PC端/移动端）、`语言`（双语/英文）、`问题描述`、`问题截图`、`UI验收是否通过`。新建行必须设 `UI验收是否通过=待验收`，否则用户视图看不到。
- `页面` 新选项不会随建记录自动出现：读字段 `property.options`（含 id），带 id 原样追加后 PUT；不要整列 PUT；改前后各导出一次 `页面` 逐条比对 0 变化。
- 不为试接口往用户表写测试行；只改自己创建的行；每套架构一致但**产品不同**，每个模块都要重新对稿，不照搬上一套。
- 基准：PC 1920、移动 390；**纯宽度差异不计**；PC 版心（线上 1200 vs 设计稿 1440）造成的“偏窄/偏小”不计。
- 逐模块从上到下，PC 与移动同类问题都查；用户每提一个问题，另一端和全表同类同步查。
- 顶栏、页脚一致不核对；页脚订阅区设计稿英文、线上德语不记。
- 英文页单独抓一遍，德语残留（选项标题、支架名称、配件清单、评价区）单独记一行，语言填“英文”。

## 2. 必记清单（每套每端过一遍）

- 字号、字重、颜色（含透明度：设计稿 `#FFFFFF@0.70` 不是纯白，不写“线上偏灰”）、下划线（设计稿节点 `td=UNDERLINE`，线上 `td=none`）。
- **标题前黄色竖条**：单独框出，写“偏细偏长、颜色偏黄”（设计稿约 `#F6A800` 4px，线上标题竖条约 `#E9BE00`，主视觉/目录竖条约 `#F5C400` 3px）；目录选中项因折行变高不算“偏长”。
- 缺失类：白底/描边/圆角、分隔线、图标圆底、缩略图浅灰底、品牌标识（图库主图左上角 LONGi / ZENDURE / SUNSHARE，PC+移动）、选择圈。
- 配件缩略图线上多出黄色描边；移动端选项缩略图内容和设计稿不同（全是首图场景图）。
- 首屏蒙版：对比左半部分/下部亮度，线上明显偏黑才记；移动端先量亮度再记。
- PC 保修页签全覆盖：各品牌保修条目、支架保修、Rechte & Service 卡片、Produktunterlagen；脚注文案（设计稿前缀 “Garantiequellen:”）。
- 移动端面包屑当前页名称被截断省略（设计稿完整显示）要记；真正偏浅的是商品副标题（设计稿 `#121212`），不是面包屑。
- 评价区（设计稿没有）与“滚到底后点页签跳页脚”：每套 PC、移动各一行放最后，配开发对话截图。

## 3. 支付按钮

- 线上首次打开是红色 Checkout 按钮，刷新后才变黄色 PayPal，且按钮上多了文字；设计稿是黄色、只有 PayPal 标识。headless 看不到黄色，不能写“线上没有显示”，用用户给的刷新前后截图并框出按钮，多张图放同一行。
- 移动端设计稿“黄色按钮 + 提示文案”对应线上首次打开的空白按钮区 + 其他付款方式链接，框要一一对应。
- 描述不抄按钮原文；颜色对了也要继续查高度、圆角、字体、提示文案字号与距离。

## 4. 描述与配图书写规则

- 一句话讲完：`标注1 XX和设计稿不一致；标注2 …。需还原设计稿。`；不加 `【模块】` 前缀。
- **不写任何数值**；**文案不一致只圈位置，不抄原文，不用「」**；德语名称换成中文（通用支架名称、双层玻璃卡、黑色铝框卡、主机参数标题、保修/产品资料标题），产品型号可保留。建行前跑正则 `px|设计稿\d|×|线上\d|「|」|【`。
- 每行约 3 个标注；编号与图中红框一一对应；同类重复元素共用一个编号；1 个标注的小行并入相邻同模块行；同一元素不跨行重复。
- 模糊行固定句式：`标注1~N 线上配图和设计稿相比同位置过于模糊，需替换高清图。（对象A、对象B）`；大图/缩略图素材一致时补“请一并替换”。判据：`naturalWidth ÷ 显示宽 ≲ 1.5` 且设计稿原图像素明显更高；保修场景图线上 ≥2× 可不记；移动端每张线上配图都要查。
- 折行与宽度差不记；折行过分造成高度变化的，写成高度问题（如“表头偏高”）。
- **编号标签不能压住内容**：按候选位置 + 底图墨迹量选位置（≥2% 视为压字则换位）；重出的图逐张看全尺寸；单侧截图给足最小宽度以免截断右侧卡片；同名文件覆盖后换新文件名再读。
- **编号 = 描述**：逐张核对“第 N 号框的是什么”与“标注N 写的是什么”；旧图抓取参数可能与上线图不同，差异大时先对比再重出。

## 5. 测量避坑

- 颜色只比默认态大图区域；设计稿 y<1000 的迷你预览缩略图会造成假匹配。
- “看似没记的小项”先看证据再记（如步骤图“白边”放大后一致则不记）；判断“看不出差别”前先量，用户肉眼已看出的优先。

## 6. 放置顺序与回读

- 新增/补记的问题必须按页面顺序放进对应模块位置，不能追加到末尾（除非用户明确要求）。行顺序靠创建顺序：要插入就把后面行内容整体上移（改描述、传新图、删旧图），用腾出的行放新内容；删自己的重复行也能腾位置。
- 批量写入慢，一律后台脚本 + 日志；换图 = 先传新图成功再删旧图。
- 回读：行数、每行附件名/数量、标注数 ≤3、编号与图一致、状态=待验收、其他页面数据 0 变化；再用关键词（偏窄、折行、折成、「」、德语名称）扫描描述。
- 汇报写清哪些没能核实（如商品页 404 无法复现刷新行为）；Figma token 只放环境变量，不写文档，用完提醒用户撤销。

## 7. 用户高频纠正

1. 写了数值 → 不写。2. 抄了页面文案/用了「」→ 只写“文案和设计稿不一致”。3. 一行 4~5 个标注 → 控制在 3 个左右。4. 编号对不上、标签压字 → 逐张看原尺寸。5. 把宽度/折行当问题 → 先比高度和间距。6. 漏黄色竖条、清晰度、下划线、标识、蒙版、支付按钮、英文页德语 → 按第 2 节过清单。7. 新问题追加末尾 → 必须按页面顺序。8. 被问“是否完全按规范”→ 先逐条对照本文件复核再回答。
