# 插件发现、技能安装与 GitHub 同步规范

仅在对应任务中读取；通用沟通、修改边界和验收规则见上级 `SKILL.md`。

## 插件发现与安装

- 当插件能直接解决当前任务缺少的能力，或能明显提高任务速度、实用性和可操作性时，可以主动发现、评估并安装；不要为了“以后可能有用”安装与当前任务无关的插件。
- 选择顺序为：已有内置能力 → 已安装并已连接的插件 → 新插件。已有能力足够时不重复安装功能相同的插件。
- 安装前检查插件来源、实际用途、所需权限、认证方式和依赖项，优先官方、精选、可信来源以及权限最小、功能边界清楚的插件。
- 用户已长期授权：免费、低风险、无需账号登录、不读取私人数据、不执行外部写入且权限较小的实用插件，在当前环境和产品规则允许时可以直接安装，不必重复询问。安装后必须验证插件已经安装或连接成功并确实可用于当前任务。
- 插件涉及账号登录、读取私人或公司数据、发送或修改外部内容、广泛文件或网络权限、付费订阅、额外购买、来源不明或其他高风险能力时，安装或连接前必须说明用途和权限并取得用户确认。产品界面或系统要求用户亲自确认时，不得绕过。
- 安装失败、依赖不满足或插件不能完成任务时，说明具体原因并寻找内置能力、其他可信插件或手动流程作为替代；不能假装插件已安装或已连接。
- 不擅自卸载、禁用或改变已有插件及其权限。只有用户明确要求，或当前任务确实需要且已经确认影响范围时，才进行这类修改。

## GitHub 与 Skill 同步

- 同步个人 skills 前，先盘点本地 `$CODEX_HOME/skills` 或 `~/.codex/skills` 与目标 GitHub 仓库已有内容。
- 按文件夹名、`SKILL.md` frontmatter 的 `name`、description 和实际用途识别重复；不要只因为文件名不同就创建新副本。
- 分类为：本地新增、远端新增、同名冲突、功能重复、完全相同。完全相同或功能重复时优先合并到更完整、更通用、已有调用历史更多的 skill。
- 删除重复项前必须能说明它与保留项的关系；不确定时先保留并标注原因，不做破坏性清理。
- 合并时保留用户长期偏好和已验证的工作流，删除泛泛而谈、过时、互相冲突或重复表达的规则。
- 修改后尽量运行 skill 校验；如果校验工具因依赖缺失无法运行，要说明已完成的手动检查和未完成项。
