# Figma Visual Handoff

用户是视觉设计师。交付目标是让前端能读懂设计、分别导出素材、调整裁切和复现布局。视觉效果、可编辑性、图片可导出性都属于完成标准。

这是独立的 Figma 专属 Skill，不替代或改写 `personal-ai-work`。当前用户指令优先；本机存在 `personal-ai-work` 时先按其确定沟通方式和修改边界。调用 `use_figma` 前必须读取当前安装的 `figma-use`；整页适配按需结合 `figma-generate-design`。本 Skill 约束设计与交付结果，工具 API 以当前工具文档为准。

## 进入任务

1. 从用户链接解析文件和节点，读取目标及相邻模块，确认实际页面、当前版本、尺寸、字体、组件、变量、图片、布局和命名。旧节点 ID 只是线索，先验证存在；不在整份文件中无差别扫描。
2. 将任务分为：局部修改、图标设计替换、PC 到移动端适配、图层交付整理。只读适用的参考：
   - 图片、Frame、素材与前端交付：[交付结构](references/frontend-handoff.md)。涉及页面创建或重排时也必须读。
   - 图标候选、精修、替换：[图标规则](references/icons.md)。
   - 响应式页面与间距：[移动端适配](references/responsive.md)。
   - 使用 Figma JavaScript 工具及处理执行错误：[已验证的问题与修正](references/figma-pitfalls.md)。
3. 简要说明目标、修改范围、保留项和交付位置。已有明确授权和已确认规则时直接执行，不为每个常规尺寸重复确认。用户要求分模块确认时只推进当前模块；用户要求先出图标候选时先展示候选，确认后替换。
4. 默认保留原稿，在明确命名的副本中适配或重组；局部替换则只改指定范围。先检查是否已有同用途版本，避免重复创建。

## 核心交付结构

- 页面及有结构关系的模块使用 Frame；文字流、卡片列表等使用自动布局。不要把所有东西塞进一个 Group，也不要把整页截成图片冒充可编辑稿。
- 图片及其蒙版、调色、渐变按导出意图放进独立的 `Media / Export` Frame。标题、正文、按钮放进同级 `Content` Frame。图片导出 Frame 内不得混入不属于图片资产的文案或按钮。
- 图片与文字可以同属一个模块 Frame；要求的是媒体和内容各有独立分支、能单独导出，不是必须把整页所有图片集中移到另一张画板。
- 首屏、图文叠加、流程图、产品卡片同样遵循媒体与内容分层。纯装饰背景可放独立 `Background` 分支。图片取景与蒙版收在媒体 Frame 内，文字保持可编辑。
- 导出 Frame 本身就是交付边界：尺寸、透明度、裁切、圆角和实际导出结果必须对应。设好 Frame 名称不代表素材已可用，必须检查内部内容及样张。
- 不为整理图层改变已确认的视觉效果、字体、颜色、间距或内容。背景、圆底和图标符号要分别辨认，避免漏复制背景或把符号错误放大。

## 实施与自查

- 先复用同站已确认的组件、样式和变量，再做必要重排。保留原图、文案、素材来源及 PC 原稿；适配不意味着重新生成图片或改写语言。
- 同级元素使用一致的边距规则；不同层级可以有不同间距。记录外边距、模块间距、标题到内容、卡片间距与卡片内边距，避免重复累加 padding 和 gap。
- 写入工具返回本次创建、修改、删除的节点 ID，以及尺寸、层级或数量等必要证据。报错时按工具的安全重试状态处理，避免留下重复版本或散落节点。
- 结构检查：可编辑文字、媒体与文字分离、导出 Frame 可独立选取、图片来源正确、字体一致、无非预期溢出。保留原组件关系，只有获准且确有必要时才解除实例。
- 视觉检查：查看整页或整模块实际截图，再检查有风险的位置；关注长文换行、按钮高度、图片边缘、焦点人物、产品完整性、图标视觉大小和灰底边界。只在发现问题后做局部修正并复核，不无变化地重复截图。
- 导出检查：按交付范围导出真实媒体样张或实际图标，验证尺寸、透明/背景、边缘和清晰度；复杂合成媒体还要确认没有混入 UI 文案。只写入成功、文件存在或尺寸正确，都不能单独证明验收通过。

## 交付

给出 Figma 成品节点链接、画板名称、修改范围和已完成的检查。有素材导出时提供实际文件及其映射；未完成检查如实说明。只有图层结构、实际画面、所要求的导出均通过后，才称为可交付前端。

本 Skill 的使用不授权修改其他历史画板、覆盖已确认稿、上传公司图片或源设计到公共仓库。同步本 Skill 时只提交 Skill 文件，不附带用户原图、令牌、本机聊天记录或整个工作区。
