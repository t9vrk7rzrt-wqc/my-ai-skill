# PC 到移动端适配

## 先学习现有网站

查看同站已确认 PC/移动端对照，读取真实画板宽度、内容宽度、字号、行高、模块间距、图片比例与裁切。先确认当前目标是否已有移动版或草稿，检查实际内容，不能因为名字像移动端就直接拿来当成品。

同站页头、页脚、品牌样式、按钮、通用组件优先复用。主要适配中间内容；不擅自重做全站、换照片、翻译文案或改变模块顺序。

## 已确认的 SolaStyle 基线

以下是这个网站本次已确认并实际使用的规则，供同站连续适配复用；新网站、其他断点或用户新要求需重新测量。

| 项目 | 当前基线 |
| --- | --- |
| 移动画板 | 390px |
| 左右外边距 | 各 20px，常规内容宽 350px |
| 主体顶部 / 底部留白 | 各 48px |
| 模块之间 | 48px |
| 标题说明组到模块内容 | 24px |
| 标题到说明 | 常用 12px |
| 卡片之间 | 常用 16px；连续安装步骤本次用 24px |
| 卡片内边距 | 按类型统一 16px、20px 或 24px，不随机逐张改变 |
| 首屏标题 | 32px / 约 38.4px 行高 |
| 模块标题 | 24px / 约 31px 行高 |
| 正文 | 常用 14–16px，约 21–24px 行高 |

“间距统一”表示同级关系有一致规则，不是把所有字号、内边距、图片比例机械设成一样。文字长短不同允许高度随内容变化；相同类型的固定高度卡片必须先确认最长内容能放下。

## 模块重排

- 图文双栏：依阅读顺序改为上下排列；媒体与文字各自独立 Frame，不能把文案烘焙到图里。
- 步骤：保留编号、顺序、原图和完整说明，改成纵向流程。旧横向箭头按布局语义调整；不能为省高度删掉步骤。
- 下载：保留资料名称、格式、图标和链接信息，用单列可读条目，不把 PDF 图标与旁边标题合并成图片。
- 安全提示：辨认完整的图标圆底与内部符号，统一容器、符号视觉占比和图文距离。
- FAQ：两栏转一栏，为问题与箭头预留独立宽度。长句自然换行，箭头不能被挤出卡片；行高随内容增长。
- 卡片、表单、产品：根据语义选择单列、两列或已有横向浏览模式，不能一律缩小 PC 的四列字体。需要横向浏览时保留已有提示/切换控件，不在纯设计稿中虚报已实现交互。

## 图片和文字

- 保留原素材，用单独的媒体 Frame 调整比例与焦点。先确认人物、手部、产品、安装连接点等重点是否完整；不能统一居中裁切所有图片。
- 需要保持全图的安装步骤图，不应因为首屏需要裁切就一并裁成横幅。原始资源像素不足时如实说明，不重新生成相似图顶替。
- 优先去掉为 PC 宽度手动插入的视觉换行，再按手机内容宽度自然换行；保留语义必要的段落和文本内容。
- 检查继承的 `textCase`、字距和变量：源文案本身小写不代表实际渲染不会被标题化。不得擅自改掉已有确认的大小写行为。
- 按钮要检查真实文字高度；14px 字号仍可能因字距或内边距换成两行。给文字足够宽度或按既有规范重排，不靠截断标签隐藏问题。

## 验收

1. 核对各模块实际左右坐标和宽度、相邻模块的真实空隙，而不只是检查设定的 gap。
2. 检查自动布局的 padding 与父级 gap 是否重复累计，边框和最小高度是否改变了卡片尺寸。
3. 单独检查图片 Frame：无非预期白边、拉伸、空图、蒙版偏移，导出不含文案。
4. 查看整页实际截图，重点放大首屏、长标题/按钮、最长 FAQ、图标及灰底起止；发现问题后局部修正并复核。
5. Figma 静态稿只证明设计尺寸下的适配；如果没有运行网站多宽度测试，不称为浏览器响应式已经验证。
