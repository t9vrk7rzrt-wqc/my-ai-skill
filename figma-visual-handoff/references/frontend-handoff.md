# 图片 Frame 与前端交付

## 页面结构

建议结构随现有命名调整，不为套模板重命名整份旧文件：

```text
Page / Mobile
├── Header                         复用同站组件
├── Hero                           模块 Frame
│   ├── Media / hero-mobile        独立图片导出 Frame
│   │   ├── Source Image           保留原图及有效像素
│   │   └── Image Effects          仅包含本次需要烘焙进图片的效果
│   └── Content                    可编辑内容 Frame
│       ├── Heading
│       ├── Description
│       └── Actions
├── Main                           按阅读顺序自动布局
│   └── Section / Installation
│       ├── Section Heading        文字 Frame
│       └── Steps                  列表 Frame
│           └── Step / 01
│               ├── Media / step-01
│               └── Content        编号、标题和正文
└── Footer                         复用同站组件
```

模块的媒体与文字可以同属一个父 Frame；不能只用一个包含图片和文字的 Group 作为唯一导出单元。用户要求素材集中区时，再额外建立有映射关系的 `Assets / Export` 区域；避免没有必要地复制整套素材。

## 媒体 Frame 的边界

1. 对每张图片设置独立 Frame，按设计中的可见范围设尺寸。需要裁切时启用 `clipsContent`；检查是否意外裁掉阴影、人物、产品边缘。
2. Frame 内保留原始图片，不能为凑手机尺寸直接压扁。记录适用的填充方式、裁切焦点、取景比例和当前变换；前端应能分辨素材本身与展示容器。
3. 合成图片需要一起导出的蒙版、局部修图和滤镜放进媒体分支。用于 UI 的半透明遮罩、渐变、圆角或阴影若应由前端实现，单独分层，并说明是否参与导出；不要同时烘焙与再叠加，造成双重变暗。
4. Logo、认证章等本身就是图片内容的品牌文字可以留在资产内；页面标题、正文、按钮和价格不得混进图片导出 Frame。
5. 叠加布局优先在外层模块控制定位：媒体在下，`Content` 在上；保持内部自动布局。媒体的绝对定位不应占据正常内容流。
6. 原图和最终取景的关系要保留。前端若需调试不同屏宽，按请求交付原图和取景样张，不只交付一张不可再调整的窄裁图。

## 命名与导出设置

- 名称体现页面、模块、用途及版本，例如 `installation/hero-mobile`、`installation/step-01-unpack`。有 PC/移动不同取景时用 `-desktop`、`-mobile` 区分。
- 照片按实际需求用 PNG/JPG；透明合成图用 PNG；可编辑矢量图标用 SVG。不得用嵌入位图的 SVG 冒充矢量图标。
- 导出倍率依据实际像素和需求选择；2×只是常用值，不是固定要求。若原图信息不足，放大画布不会自动增加细节。
- 为需要交付的媒体 Frame 设置导出预设；不把整个 UI 模块设置成唯一的图片切片。图标通常独立 SVG 导出，背景圆底是否一起导出需明确。
- Figma 工具的倍率上限随当前接口核对；历史工具 `defaultScale` 最高为 4。超出时采用目标尺寸导出副本等受支持路线，不能只改文件名或伪报分辨率。

## 验证与前端映射

抽查最复杂的合成媒体、最容易裁切的图片和真实尺寸最小的图标；用户要求全量导出时检查全量。确认独立导出后没有标题、按钮、漏图、意外白边或透明通道变化。保留来源与设计稿对应关系。

交付信息按实际需要提供，字段可简化：

| 字段 | 内容 |
| --- | --- |
| 设计定位 | 页面 / 模块 / Figma 节点链接 |
| 媒体资产 | 导出 Frame 名称、格式、真实像素、倍率 |
| 显示规则 | 展示宽高或比例、填充方式、裁切焦点 |
| 实现分工 | 渐变/圆角/阴影由图片包含还是前端实现 |
| 内容结构 | 对应 `Content` 分支；文字和按钮仍可编辑 |
| 检查结果 | 实际导出样张、截图、已知限制 |

完成设计不等于前端代码已经实现或交互已经可用；不要混淆视觉稿验收与网站上线。
