# 图标设计、替换与交付

## 先读取模块，再生成

- 精确识别目标、原容器和相邻至少几个同类图标。读取线宽、颜色、端点、连接方式、视觉占比、内部留白、圆底和图文距离。
- 不把某次使用的 24×24、1.6px、黑色或红色当成所有页面的固定规范；同一网站不同模块也可能不同，以当前模块和用户要求为准。
- 有用户素材包时先确认真正使用的 SVG 文件和版本。优先保留语义特征，用简化细节、组合层级与光学居中匹配模块。
- 用户要求先确认时，用真实尺寸和放大图展示可编辑 SVG 候选。记录用户最终选中的文件名/版本，不能擅自换成后来推荐的版本。

## 视觉标准

- 数值大小一致还不够：统一视觉重量、线宽、轮廓复杂度、圆角、留白与光学中心。在最终 24px、32px 等实际尺寸检查，不只看放大图。
- 线条避免粘连、毛刺、突起、断接、飘浮碎片、交叉形成黑块；需要空心的轮子、孔洞不能被其他线穿过。
- 浅色背景圆/底板与内部符号是不同层级。移动端缩放应缩放完整图标容器或明确的符号尺寸，不能漏掉圆底，也不能将内部 21px 符号放大到 48px，而旁边却是 48px 圆底加 24px 符号。
- “两种纯色、无高光”严格只用背景与图标两种颜色，不加阴影、渐变或额外高光。
- 原 SVG 是填充轮廓时，不能承诺直接变成完全一致、可调线宽的中心线。保真与重绘为真实描边是不同交付，按用户需求选择。

## 替换边界

1. 按用户限定只替换目标图标。保留容器、坐标、尺寸、底板、文案、卡片、布局及其他图标。
2. 先备份实际旧 SVG 或保留可回退副本，再导入真实最终 SVG。矢量导入优先使用 `figma.createNodeFromSvg`，不要用位图顶替。
3. SVG 显式设置 `viewBox`、画布尺寸与所需描边；`currentColor` 导入时可能变黑，须按目标模块核对真实颜色或变量绑定。不要用旋转线段临时拼一个近似图标冒充提供的资源。
4. 如果新资产带有不对称空白，调整其内部构图与光学居中，不随意移动原容器去补偿。
5. 输出明确的创建、修改和删除节点 ID；避免错误解除嵌套实例导致祖先 ID 失效。

## 验收与素材

- SVG 能解析；可用时运行 `xmllint --noout`。解析成功不等于图形正确。
- 同时查看模块整体和目标实际尺寸；核对线宽、端点、连接、颜色、四周留白、图文距离和裁切。
- 严格“只替换一处”时，对比替换前后容器及周边布局；适合时加像素差分，但抗锯齿差异须结合实际画面解释。
- 交付真正写入 Figma 的最终 SVG，附对应节点及文件名。图标导出 Frame 内仅包含本次需要的符号/底板，不包含卡片文字。
- 旧 `figma-icon-replacement-qa` 已存在时可结合使用，不另建功能重复的图标 Skill，也不自动覆盖或删除旧 Skill。
