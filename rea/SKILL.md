# REA 手动调用入口

## 启动边界

- 只有用户明确发出“调用REA开始完成这个工作”或同义的立即执行指令时，才启动本次 REA 工作。引用口令、讨论未来调用、安装配置或询问用法不算启动。
- 口令授权当前明确的任务；不授权后台监控、定时执行、后续无关任务或自动更新。
- 未收到启动指令时，仅回应或整理需求，不调用 REA 分析工具、不打开分析目标、不运行目标程序。
- 用户要求安装与检查时，可以执行版本、配置、MCP 握手和工具列表检查；这些检查不得分析用户目标。

## 启动后的工作

1. 从对话和工作区确认目标、问题、保留边界和输出位置；只追问影响执行的缺失信息。
2. 读取 [安装与来源](references/installation.md)，并读取已安装 REA 包中 `skills/reverse-engineer-anything/SKILL.md`。按目标类型加载其相关 references；以当前连接的工具列表和实际输入结构为准。
3. 优先使用已连接的 `rea` MCP 服务。当前会话尚未加载服务时，可以通过已验证的本机 CLI 执行；不得把 CLI 可用称为当前会话 MCP 已连接。
4. 在用户指定范围内分析。普通完整源码仓库分析优先使用常规代码工具；REA 主要用于发布包、应用行为、反编译和运行证据。
5. 区分直接观察、推断和未知项，保留证据位置与工具限制。需要构建或修改时，使用正常开发工具完成并验证，保留未指定内容。
6. 原生分析按目标选择已有引擎；缺少 Hopper、Ghidra、IDA 等依赖时明确报告，不宣称所有能力已就绪，不自行购买或安装不相关工具。

## 交付

用中文说明完成内容、证据、产物位置、验证结果和未完成项。关闭本次打开的分析会话。不要仅凭安装成功声称实际任务完成。
