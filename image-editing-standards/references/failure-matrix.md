# 问题库：现象 → 应对 → 验收

来源为本机任务中的用户反馈、可见失败及未证实交付。技术防线中超出直接反馈的部分属于建议方法，不冒充历史根因的已验证结论。去标识案例见 cases.md；原始证据保留在各任务本机目录。

## A. 理解、对象和版本

| 编号 | 问题/触发条件 | 应对方案 | 不通过条件 |
|---|---|---|---|
| A01 | 任务/输出可能不匹配，或旧摘要把后续授权误判为串任务 | 读完整需求变更再判断；绑定本轮输入、对象、输出路径 | 真正输入目标不匹配，或断章取义归责 |
| A02 | 圈中板面透视和栏杆，却修夹具或指甲 | 标注图叠对原图；分别列目标；逐项前后核对 | 任一被点名对象未处理 |
| A03 | 去水印交付成场景下移 | 将“操作”写成可观察的变化；在目标局部验证 | 有新文件但目标仍在或做了别的操作 |
| A04 | “不直修枝”等歧义被臆测 | 先结合原图核实；仍影响操作时只问关键含义 | 未理解就执行无关任务 |
| A05 | 用户还在说三个问题，助手提前生成 | 保持收集状态；用户说完后整合范围 | 漏掉后续要求或先改了正式文件 |
| A06 | 最新有效版本与最初照片混淆 | 分别登记人物来源、产品构图来源；建立版本链 | 为恢复人物把已认可的产品位置退回旧版 |
| A07 | “开始/继续/嗯”被视为图片最终认可 | 记录反馈对象及上下文；区分执行许可和验收 | 无明确整图确认却标“最终确认” |
| A08 | 附件失效靠记忆补图 | 检索稳定副本、哈希及来源；找不到则索要 | 生成相似图冒充原件 |
| A09 | 图片仅供参考尺寸，却被照着原场景修改 | 分清尺寸参考、内容参考和编辑母版的角色 | 需求是按文案新生图却继续复用错误主题 |
| A10 | 用户明确重新生成，却只调整原图色调 | 区分新生图、局部编辑、调色三种操作；按最新要求执行 | 操作类型不符，或以暖色滤镜代替新内容 |

## B. 修改边界与累积返工

| 编号 | 问题/触发条件 | 应对方案 | 不通过条件 |
|---|---|---|---|
| B01 | 修两条边重生人物、背景、整块板 | 最小授权范围；锁定母版；检查区外变化 | 保护区出现未授权改变 |
| B02 | 补厚度后透视坏了；修人物后构图坏了 | 每轮回归核对构图、四角、遮挡、纹理、厚度、人物 | 本轮改善但任何已确认项退步 |
| B03 | 局部调色变成整图偏色 | 局部范围内匹配亮度和色温；保护其他区域 | 天空、建筑、肤色随同变化 |
| B04 | 去部件后残影、旧阴影、空洞仍在 | 修物体及其属于授权范围的接触痕迹；补连续背景 | 悬空影、复制纹理、断栏杆或异常线条 |
| B05 | 返工层层叠加、结果更糊 | 回退最后有效母版；替换失败层，避免重复编码和插值 | 旧黑边/旧侧面/接缝叠在新层上 |
| B06 | 用扩大的掩膜掩盖越界 | 掩膜执行前按目标定义，柔边和阴影预留也登记 | 看了差异后把掩膜扩成全图才“通过” |
| B07 | 反复同一提示词抽图 | 诊断是识别、素材、几何、遮挡、分辨率还是工具限制 | 没有策略变化且同类错误重复 |

## C. 产品真实性与几何

| 编号 | 问题/触发条件 | 应对方案 | 不通过条件 |
|---|---|---|---|
| C01 | 声称“用包内全黑组件”但只有相似生成纹理 | 记录压缩包成员、真实型号及SHA-256；说明参考或实际合入 | 无来源证据却声称原素材替换 |
| C02 | 横装组件电池片线条方向与素材不符 | 对真实正面旋转/透视关系核对，不独立画线 | 随意改片数、半片分区、栅线方向 |
| C03 | 54HVD侧框露出大块亮银金属 | 正面和侧面交叉对照；区分浅色内沿和外侧框 | 用通用银边替代该型号细节 |
| C04 | 板子像纸片，补后又像厚黑块 | 用真实侧视比例与当前视角判断厚度 | 没厚度或靠描边/投影/夸张倒角冒充 |
| C05 | 左右边分别变形导致“拧过来” | 以整块板统一坐标关系定义正面、框体和侧面；检查四角 | 竖边侧向、亮暗或接点与板面冲突 |
| C06 | 窄条修好但上下框接不上、PS感重 | 同时看整块板和四转角；修窄带时保持邻域连续 | 台阶、双线、黑刃、硬缝、光带不连续 |
| C07 | 两块板处于同平面却中缝折转 | 核对共同平面、安装角度与消失关系；不能只凭大小 | 空间关系无法解释，或无依据宣布几何正确 |
| C08 | 横梁弯、边框波浪或不共线 | 建立端点、中心线、边界；在当前透视下检查直线 | 几何本应为直线却有无依据弯曲 |
| C09 | 夹具、支架与EUP020图纸不符 | 对照可见连接、受力和固定位置；删除明确错误部件 | 把生成图本身当结构权威 |
| C10 | 支架藏起来但安装关系仍解释不通 | 追踪栏杆→固定件→背框的可见连接；遮挡不等于证实 | 悬空、穿透、支架与板背无连接逻辑 |
| C11 | 细铁丝、假扣件、无用途零件 | 每件新增物体追问来源和连接；无依据且在授权范围内去除 | 无法解释的细条、零件重复或残段 |
| C12 | 被遮挡背架、图纸没写颜色却称精确复刻 | 仅报告可证实部分，必要时标安装示意 | 猜测颜色/隐藏结构并当实物事实 |
| C13 | 栏杆穿板、手指穿框、遮挡前后反转 | 明确前景/产品/人物/支架层级与交点 | 任一不合理穿插或缺失轮廓 |
| C14 | 小灯硬加太阳能板，主题不明确且场景生硬 | 先用真实使用逻辑表达模块主题，再选择合适场景 | 为拼主题强行搭物件，用户看不出含义 |

## D. 人物、自然感与材质

| 编号 | 问题/触发条件 | 应对方案 | 不通过条件 |
|---|---|---|---|
| D01 | 只调回肤色却脸、衣服、纹理都变了 | 身份和纹理要求不变时使用原照片的获授权保留路径 | 均值色接近却仍是生成的人物 |
| D02 | 蜡皮、雕塑感、血管纹理不对、面部白点、胡须丢失 | 局部修异常；保留原稿毛孔、发丝、胡须、真实血管起伏 | 塑料皮肤、过锐颗粒、换脸或原人物细节缺失 |
| D03 | 指甲、手部、肢体异常 | 核对数量、关节、受力及与物体接触；不顺便改其他人 | 拇指方向/握持/遮挡解释不通 |
| D04 | 不锈钢像塑料或大片纯白反光 | 匹配场景光线、粗糙度、细小反射和边缘高光 | 材质与环境脱离、硬亮条或脏糊涂抹 |
| D05 | 冰雹像雪团、棉花、塑料球；水珠质感不对 | 雹粒用不规则冰体与局部透光；水珠核对附着、反射、尺度及玻璃关系 | 毛绒、规则球、装饰性塑料珠或不合理反射 |
| D06 | 云与建筑割裂，光影不统一 | 只软化指定云区，保护建筑轮廓；对照整体光线 | 建筑边缘变形、天空色温无授权改变 |
| D07 | 上下割裂、局部偏蓝、反复蒙版导致脏、树和背景过假 | 分清过渡/色偏/纹理问题；按实际字色设计可读区，少量局部处理；核对植被形态 | 厚蒙版、全图模糊/滤镜盖问题，或黑字背景被一概压暗 |
| D08 | 暗棕渐变呈焦黑脏重感 | 本类明亮卡片依用户反馈改明亮干净方向，先做可比候选 | 把一次项目偏好泛化成禁止所有深色图 |

## E. 清晰度、尺寸、透明与导出

| 编号 | 问题/触发条件 | 应对方案 | 不通过条件 |
|---|---|---|---|
| E01 | 130×130缩小居中变成1254×1254新设计 | 原画布内同比缩放目标；记录主体边界和中心 | 新画布、新阴影、新框架、非等比变形 |
| E02 | 要同尺寸清晰化却扩大、裁切 | 锁定像素宽高；清晰效果和尺寸分别检查 | 只改DPI或插值冒充细节恢复 |
| E03 | 找高清原图却重新生成相似图 | 先查生成原件、历史来源；比较内容与裁切 | 新图被称为“找回原图” |
| E04 | 454×204交付图被当高清母版 | 保存实际生成母版与网页缩略图；标注真实尺寸 | 放大缩略图被称为原生高清 |
| E05 | 4K、高清、超清只有文件名 | 读取真实尺寸与来源；注明背景/组件各自清晰度 | 宽高或生成方式与宣传不符 |
| E06 | PNG透明变白底/棋盘格，黑白边 | 查alpha通道和半透明边缘；深浅背景看边 | 有alpha通道但所有像素不透明；棋盘格烙入RGB |
| E07 | 下载未完就读图，损坏图打包 | 下载结束后解码、检查格式；再压缩并测试 | 后缀正确但文件截断/不可解码 |
| E08 | .larkcache误当ZIP，素材未真正提取 | 识别文件类型；检查压缩成员与CRC；只提取可信路径 | 未解包成功就声称素材齐全 |
| E09 | 生图文字、按钮、logo被无授权添加 | 模块图明确是否有字；网页文字保持可编辑来源 | 伪字、错字、无授权按钮/品牌标记 |
| E10 | SVG只是嵌PNG却声称可编辑矢量 | 检查SVG结构、位图嵌入和实际渲染 | XML有效被误当完整可编辑或真正矢量 |
| E11 | 图片单看正常，网页裁切丢重点 | 按真实容器比例检查产品、人物和文案安全区 | 标题压产品、裁掉主体/头手或边框 |
| E12 | 为凑尺寸硬截画面，模块割裂 | 按目标比例组织适合的内容；用户要求仅删两侧天空时严格按该裁切 | 主题不完整、主体截断、图像像随意截屏 |
| E13 | 右下元素没有贴到原先角落位置 | 明确相对于画布还是图片可见内容对齐；检查实际容器边缘 | 尺寸相同但锚点、裁切或留白与约定不符 |
| E14 | 矢量化后反而糊，误以为SVG必然高清 | 根据源内容选择原生导出/保留位图/真正重绘；实际尺寸比对 | 模糊位图封装SVG，或描摹丢失细节却宣称无损 |

## F. 验证和交付

| 编号 | 问题/触发条件 | 应对方案 | 不通过条件 |
|---|---|---|---|
| F01 | 输出存在就说任务完成 | 目标逐项前后对照，检查最终保存文件 | 没打开结果或修错位置 |
| F02 | RGBA差异边界空，误以为RGB未变 | 分别检查RGB、alpha；逐像素按任一通道变化计数 | 依赖差异图alpha包围框导致漏报 |
| F03 | 区外零变化就宣布透视/产品正确 | 技术范围与视觉语义分别给结论 | 不自然边框靠数字“验收通过” |
| F04 | 只给局部图掩盖整图退步 | 同倍率局部＋整图＋实际显示尺寸 | 只看缩略或放大，不看整体关系 |
| F05 | 旧核验报告对应新输出 | 最终文件SHA-256与报告绑定；改后重验 | 输出改写后仍引用原报告 |
| F06 | 没见用户确认却叫最终定稿 | 保存确认原话、对应版本和认可范围 | 将未确认/继续返工版本编入成功标准 |
| F07 | 只有预览或失效链接，无可用文件 | 检查最终路径、格式及压缩包内容 | 用户无法拿到正式结果 |

以上共60项防线（A10、B7、C14、D8、E14、F7）。数量不代表历史独立错误次数；部分条目拆分自同一返工链。
