# 文件、像素与视觉验收

## 一、四种结论不能混用

| 结论 | 所需证据 |
|---|---|
| 文件已生成 | 最终路径存在，完整解码；工具成功不单独算 |
| 技术核验通过 | 宽高、格式、透明和授权范围符合任务卡；报告绑定SHA-256 |
| 视觉自检通过 | 实际看过最终整图、100%局部、使用尺寸，目标与回归项均通过 |
| 用户最终确认 | 用户针对明确版本、明确范围的认可；保存原话及关联 |

技术核验通过不能替代用户确认；用户局部认可也不能覆盖尚未修复的问题。

## 二、文件检查

1. 读取真实尺寸，区分像素宽高和文件字节大小；PNG扩展名不证明格式正确。
2. 完整解码，而非只读头部。正式文件复制/导出到目标目录后再次检查。
3. 透明任务检查通道、非全不透明像素、半透明轮廓、背景是否烙入。PNG有alpha但alpha全255不算透明图。
4. 元数据记录ICC、EXIF方向、色彩模式。若为比较执行统一解码，记录归一化步骤；不允许静默调整实际交付图。
5. ZIP检查成员齐全和CRC；每个正式图单独可解码。SVG检查XML与实际渲染，并说明矢量/文字路径/嵌入位图的性质。
6. 重编码可能改变元数据和压缩字节；文件哈希不同不等于像素变了，像素相同也不等于来源相同。

## 三、严格保护区

坐标使用最终原始像素，左上角(0,0)。掩膜白色允许修改，黑色保护。范围必须在编辑前按用户目标确定，柔边/阴影范围也要计入；不可在看到输出以后扩大至所有变化像素以获得通过。

参考脚本命令：

```bash
python3 scripts/verify_image.py --source /absolute/before.png --result /absolute/after.png --allowed-mask /absolute/allow.png --protected-box 0,0,500,500 --require-alpha --report /absolute/qa.json
```

- Python3和Pillow是检查依赖。缺依赖时说明，不伪报通过；可用环境内其他只读图像库实现等价检查。
- 掩膜只接受同尺寸单通道L模式PNG，0全保护，任意大于0的值视为允许。该定义支持羽化区，但不会把灰色解释为“可变动的幅度”。
- `--protected-box x0,y0,x1,y1`是左上包含、右下不包含的矩形，可重复。保护框与允许掩膜相交时，保护框仍要求零变化。
- 默认RGB和alpha逐通道精确比较，阈值为0。JPEG有损输出可能使全图像素改变；要求逐像素保留时应交付可行的无损格式，不能偷偷放宽阈值。
- 同尺寸才进行同坐标比较。尺寸不同直接判为该项失败，不把图自动resize成相同大小后声称原始像素保留。
- 脚本同时报告RGB差异、alpha差异、RGBA差异和可见像素差异；透明区隐藏RGB也计入严格原始RGBA差异。
- 报告包含输入/输出/掩膜哈希、尺寸、格式、模式、方向及ICC哈希；检查后若文件变化，报告失效。
- 未给掩膜时只报告差异，不能结论“区外不变”；单独指定的保护框可以获得对应局部结论。
- 源文件有非默认EXIF方向、帧数非1、ICC/方向不一致时，脚本保守判为未通过，需要先明确坐标和显示解释。它不能评估色彩管理后跨软件的观感。
- 脚本退出码：0为所请求技术条件满足；2为条件失败；1为输入/依赖错误。无掩膜运行的0只意味着已请求项目通过，不是整体图像合格。

核心定义：

```text
changedRGBA(x,y) = 任意一个RGBA通道与源文件不同
outsideChanged = 允许掩膜为0 且 changedRGBA 为真 的像素数
严格区外保留要求：outsideChanged == 0
```

不要直接用RGBA差异图的alpha包围框代替RGB检查：某些图像库在alpha无差异时可能得到误导性的空边界。

## 四、视觉检查

### 整图

主体、构图、人物、天空、建筑、地面、前后遮挡、色温和留白，与本轮母版及已确认项一一核对。检查有无多余物体、被裁内容或无授权的增强。

### 100%与局部

100%表示显示像素与图像像素对应，不能把缩略图放大当原图。放大对照采用同坐标、同倍率、同色彩解释：人物脸手衣纹；组件片区与格线；侧边和四转角；栏杆交点；固定连接；阴影边界；修复带两侧。

整块物体也要看：窄边单看挺直，不代表放回板面就没有扭转。差异热图只能定位改动，不能判定质感。

### 实际使用尺寸

按真实网页/Figma容器、裁切方式和文字位置检查。原图可能是1792×768，页面图是454×204，两者长宽比不相同；记录裁切而非声称完全同构图。标题安全区和不同端裁切按项目实际要求，不自行发明固定比例。

### 三项硬否决

- 任务不匹配：图/对象/问题/版本错误。
- 保护失败：未授权区域改变或已确认项目退步。
- 真实性失败：指定产品、空间关系、安装连接明显不成立。

任何一项不能靠总体平均分抵消。不设虚构“95%准确率”或“100%还原”承诺。证据不全则保留未验证状态，明确其实际影响。

## 五、何时可以结束

本轮所有必须项与回归项通过、实际文件可读取且链接正确、声明与证据一致时可以交付。用户最终确认尚未发生就写“修订稿/供确认”，不无限等待，也不提前标为最终确认版。
