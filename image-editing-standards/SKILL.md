# 生图即修图规范

## 目标与适用边界

把用户指定的改动落实到正确的原图和对象，保住已确认成果，交付经过检查的可用文件。严苛程度体现在证据和否决条件，不能承诺百分百准确，也不能用繁琐流程代替实际修改。

本规范从真实任务复盘中提炼，公开仓库仅保留通用规则与去标识案例。用户最新明确要求优先；项目中的尺寸、颜色、型号和坐标必须重新读取，不能沿用案例数值。遵守当前系统、工具、技能和权限限制。

## 必须遵守的十二条

1. **先识别输入和任务。** 打开实际原图和标注图，写明输入文件、对象、要改的问题、输出去向。不能把其他聊天的文件当成本轮结果。
2. **原图与参考分工明确。** 编辑母版、构图参考、产品正面、产品侧面、支架图纸、风格参考分别登记。参考风格不等于授权改构图；相似产品不等于指定型号。
3. **只改指定处。** “其他不变”覆盖人物、背景、画布、坐标、形状、文字、色温、材质及未指定产品细节。局部修复不得默认全图再生。
4. **已确认项必须同时成立。** 修人物不能退回错误产品透视；补厚度不能改电池片；修边框不能弄坏板面。检查本轮目标，也检查全部已确认项。
5. **保留最新有效母版。** 原始照片可能负责人像，另一个已确认版本负责产品构图。允许分层采用不同来源，但明确来源和空间关系，不能擅自统一退回最早版本。
6. **真实产品要有真实证据。** 查型号、正侧面、栅线方向、黑框与浅色内沿、边框厚度。只把图交给生成器作参考，不能声称已经精确使用了原素材。
7. **整体几何先于局部质感。** 板面、框体、侧边、转角共享一致空间关系。不同安装平面可以有不同消失关系；同一平面不能分段任意扭曲。不要靠加黑边冒充厚度。
8. **生成候选不等于成稿。** 按当前可用的 `imagegen` 技能和工具完成生成/编辑，不伪造参数或改用未授权的外部接口。工具成功后仍需查看实际输出。
9. **保护像素要验证。** 只有对同一坐标系、同一画布的最终保存文件完成保护区差异检查，才可说该区域像素未变。提示词写了“不要变”不算证据。
10. **视觉和数字分别验收。** 差异为零只证明对应范围未改变；不证明透视正确、接缝自然、人物真实或用户满意。
11. **确认状态不可夸大。** 区分已生成、技术核验通过、视觉自检通过、用户局部认可、用户最终确认。“继续”“嗯”“开始”不能脱离上下文当作整图验收。
12. **失败要回退和换方法。** 保存有效母版和未通过候选。连续两轮同类缺陷未改善时先诊断并改变处理路径，不盲目重抽；这是诊断触发点，不是自动停止或扩权许可。缺原件、保护约束冲突或结构证据不足时明确阻碍。

## 执行流程

### 1. 建立本轮任务卡

读取 [任务卡与提示词](references/templates.md)，填本轮需要的字段。简单且唯一的改动可简写，不能跳过输入识别。

- 输入文件是否存在、可解码、版本是否正确；尺寸、色彩模式、透明信息和SHA-256。
- 标注图对应哪个原图；圈的是板面、侧边、栏杆、夹具还是人物；列出每个对象。
- 必须改什么，必须留什么，禁止什么；适用的实际页面尺寸及裁切。
- 输出尺寸、格式、透明要求；新文件名、母版及版本链。
- 将用户明确认可的项目列为回归检查项。认可只限有证据的范围。

用户在收集需求时先记录，等其说完再动手。已明确授权开始的任务直接执行；只在缺失信息会改变结果时问一个关键问题。附件丢失时先查本机及历史路径，确实找不到再索要；不得凭印象造替代原件。

### 2. 选工作路径

| 情形 | 路径与必读内容 |
|---|---|
| 全新场景或主题配图 | 当前 `imagegen` 技能；[工作方法](references/workflows.md)的全新生成与模块配图 |
| 原图局部修复、只改圈中区域 | 当前 `imagegen` 技能；[工作方法](references/workflows.md)的保护区及局部修复 |
| 真实组件替换、安装结构、边框厚度 | [工作方法](references/workflows.md)的产品、几何与安装章节；同时核对真实素材 |
| 肤色、人物、蜡感、白点、材质或自然物 | [问题库](references/failure-matrix.md)对应行，再读工作方法对应部分 |
| 清晰化、同尺寸缩放、透明图、导出 | [验收规范](references/acceptance.md)；不默认重设计或放大 |
| 查历史最终稿或沉淀对比案例 | [对比案例规则](references/case-method.md)；先确认版本和用户反馈 |

位图生成和编辑默认按当前 `imagegen` 技能执行；原生SVG/Figma图层的修改使用对应专门技能。只在用户明确要求或当前规则允许的情况下使用确定性合成/像素处理。**检查脚本只读图像，不赋予任何图像编辑权限。** 工具若不能保证严格保留，不以提示词保证代替结果；说明限制并选择获授权的可逆方案。

### 3. 执行并控制版本

保存原件；候选与最终稿分开，禁止覆盖未授权的源文件。每轮只处理当前明确的问题组，沿用锁定母版与已确认项。生成器输出若改变尺寸、人物或背景，不能直接视为局部修复合格。若需要扩大范围或重新生成，先判断用户已有授权；授权不明时只问新增范围。

### 4. 完成四类检查

按 [验收规范](references/acceptance.md)检查：文件真实完整；目标问题解决；已确认项未退步；实际使用尺寸能看清且裁切合理。整图、100%原始像素、问题局部都要检查；需要时在真实Figma容器中验收。不能只看缩略图。

同画布严格保护任务可运行：

```bash
python3 scripts/verify_image.py --source /absolute/source.png --result /absolute/result.png --allowed-mask /absolute/allowed.png --report /absolute/qa.json
```

掩膜使用同尺寸单通道L模式PNG，白色允许改，黑色保护。柔边也必须预先计入授权范围。脚本默认逐通道精确比较RGBA，并分别报告RGB、alpha和可见像素；输入尺寸不同则拒绝同坐标差异结论。细节见验收规范。

### 5. 交付与状态

给可用的新文件链接，简述改动、实际尺寸、完成了哪些核验、仍有哪些限制。用户要看图时显示实际最终文件。需要比对时提供原图/修改后同区域同倍率对照；不要只给漂亮预览。证据与输出版本哈希相互对应，不能拿旧报告认证新文件。
